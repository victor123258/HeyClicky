# Security notes

This is an experimental local desktop agent, not a sandbox. Keep desktop approvals enabled. Never provide secrets or permit commands you do not understand. Arbitrary approved PowerShell has your Windows user's permissions and can bypass all application-level boundaries. Prompt-injection defenses are best effort; screenshots, files and websites can contain adversarial instructions.

Main-process IPC is limited to the local fallback panel and notch workspace, and their main frames. The notch has an explicit action allowlist; the overlay has no command bridge. Expanded-notch approvals expose complete arguments, default focus to Deny, and use the same main-process ID/timeout validation as the fallback panel. Renderers have Node integration disabled, context isolation and sandboxing enabled, no generic IPC bridge, and a restrictive CSP. They render model text with textContent, not HTML. The model cannot select an arbitrary network API endpoint. No credentials belong in Git, logs, test fixtures or renderer storage.

The key is stored through Electron safeStorage (Windows DPAPI). Failure to encrypt does not fall back to plaintext. Approval is one action only, bound to a random ID, and expires on cancel or timeout. Read-only data access can expose secrets and always requires approval. All commands require approval regardless of the desktop approval preference.

Report security problems privately to the repository owner through GitHub's security reporting facility if enabled; otherwise ask the owner for a private contact without posting exploit details or credentials publicly. Review SECURITY.md, README.md and the Windows checklist before distributing this unsigned application.

Desktop tasks are serialized, not parallel. Histories are text-only and isolated per task; no task queue is persisted to disk. The voice-key helper polls only configured shortcut combinations. With Windows input, partial speech is local. Edge input may send audio to Microsoft as soon as recognition starts, including partial or cancelled speech; it does not create an AI request before release. Focusable text UI exists only in the deliberately expanded notch; hover peek stays non-activating.


## Optional Edge speech boundary

The opt-in helper uses actual Microsoft Edge on `http://127.0.0.1:21843`, bound only to IPv4 loopback. The bridge checks exact Host/Origin, does not enable CORS, denies framing, uses a restrictive CSP/no-store, and requires a random per-run bearer capability for events and the command stream. The launch fragment is moved to session storage and cleared from the URL. This capability controls voice recognition only; no AI key, screenshot, task content or generic desktop IPC is exposed to the helper. An untrusted local process running as your user is outside this boundary and could inspect browser processes/storage.

A persistent, dedicated Edge profile stores site permissions/browser data, separate from normal browsing. Permission cannot be forced permanently. A visible successful recognition test plus explicit disclosure checkbox gates automatic minimized-launch consent. No permission bypass, headless mode or microphone-indicator suppression is used. Version 1.5 adds an explicit experimental hidden-window preference, separate from background permission; the default is still minimized. Hiding only the dedicated native window is not hiding OS recording indicators. Restore uses the same exact dedicated-profile match and can find hidden windows. A launch flash, permission prompt, suspension or browser-policy failure is possible. Recognition can send audio to Microsoft, even if the user later cancels; Microsoft's service terms/retention are independent of OpenRouter. Browser caches are outside the app's in-memory audio/transcript guarantee.

Stop invalidates the active provider callbacks, sends recognition abort and expects a stopped acknowledgement. An unresponsive helper is asked to close after two seconds. Window operations match only msedge processes with the exact dedicated `--user-data-dir` argument, not normal Edge windows. Closing is best effort; if blocked, manually close the dedicated helper. Quit requests closure; Delete local data also removes its profile with bounded retries and reports locked-profile failures. Neither retracts remote audio. Fallback is permitted only before release and before any delivered dictation, with a repeat notice; stale provider events cannot submit a second request.


## Clock and tool protocol (1.5)

The local clock tool and simple clock-question path read only the device date/time and ICU timezone rules; no external time service, desktop command or approval is needed. Accuracy depends on system synchronization. Clock context (including the device timezone) may be included in AI requests. Talk now also offers `fetch_url`, but every fetch still needs approval; it does not gain desktop write/command tools. Existing web-fetch limits and prompt-injection caveats apply. Version 1.6 adds approval-gated, best-effort public HTML web search; it is not a guaranteed search API.

OpenRouter requests with tools require compatible provider parameter support; malformed/duplicate/truncated tool-call envelopes fail before execution. Batch tool responses are completed before new image messages. API errors never surface untrusted remote response bodies. These protocol defenses do not guarantee model reasoning, correctness or safe tool selection; keep approvals enabled.


## Research, generated documents, visuals and workers (1.6)

`search_web` always requires approval of the exact query; it contacts the fixed DuckDuckGo public HTML endpoint (no redirects, bounded response). Search results and fetched pages are untrusted data, not instructions or verified evidence. Every follow-up URL read also asks, even if desktop approvals are disabled. Queries go to the search service; approved source text/tool results go to the selected model. Availability and remote retention are outside the app's control.

`create_document` always asks for the exact absolute path, format, title and content. DOCX is generated locally, PDF uses escaped content in a hidden sandboxed JavaScript-disabled print window with CSP blocking external resources, and text/Markdown are literal data. This tool uses exclusive creation and refuses overwrites; other explicitly approved file tools retain their existing behavior. Exports are not automatically opened. No document macros, templates or model-generated executable markup are accepted. Abort prevents later commits where possible, but an already started/finished file write may remain.

Visuals accept bounded structured JSON only: chart values, node/edge diagrams or primitive 3D geometry with bounded positions/sizes/colors. Unknown fields are discarded. Text uses textContent/canvas; no generated scripts, raw HTML, shader code, external textures or arbitrary model URLs are accepted. Three.js is bundled locally. Session visual retention is capped at eight scenes. WebGL/driver failures are possible, and displayed diagrams are not evidence of physical/financial/scientific accuracy.

Two background workers have independent AbortControllers and text histories and an explicit restricted tool allowlist. They have no screenshot, desktop input, URL opening or shell tools, and safe dispatch rejects unsupported operations a second time. This is a capability restriction, not an OS sandbox for approved file access. They may share the filesystem and your model account; review concurrent writes and credit usage. Approvals are globally serialized, job-bound and abort-aware. Stop/quit aborts workers and queued approvals; late results cannot complete cancelled jobs. Default limits are two concurrent jobs, 12 model turns each and 15 minutes. No persistence/resume after quit, autonomous service deployment or parallel desktop control is provided. The model may receive a suggested Documents-directory path for document-related requests.
